# src/decomp — readable SLUS_206.49 decomposition

Generated by `tools/decomp_split.py` from `SLUS_206.49.c` (raw Ghidra-style export,
162,665 lines, 14,439 functions).

Rule for addresses: `FUN_xxxxxxxx` == ELF vaddr `0x00100000 + xxxxxxxxxx`.

## Layout

```
src/decomp/
├── real/                     one clean .c file per recovered function (440)
│   ├── packed_bits_write.c   FUN_0010e780  core/bitstream
│   ├── packed_bits_read.c    FUN_0010ee50  core/bitstream
│   ├── gaussjordan_solve.c   FUN_003a0730  math/matrix
│   ├── ...                   (see inventory.csv)
├── inventory.csv            address, raw FUN_ name, assigned symbol, module,
│                            body bytes, kind (real|stub)  — 14,439 rows
└── stub_addresses.txt        the 13,999 halt_baddata() addresses, hex per line
```

## Status

- **440 real, documented bodies** — functions whose code the decompiler produced.
- **13,999 stubs** — only `halt_baddata();` (bad-instruction data). These do not
  carry recovered code.
- **18 positively identified** (renamed in `real/`). Every file keeps its raw
  `FUN_` name in the header so it always cross-references the original address.

## Add a symbol

Edit the `SYMBOLS` table in `tools/decomp_split.py` (addr -> name/module/note),
then re-run:

```powershell
python tools/decomp_split.py SLUS_206.49.c src/decomp
```

New symbol names are reflected in `real/*.c` filenames and `inventory.csv`.
