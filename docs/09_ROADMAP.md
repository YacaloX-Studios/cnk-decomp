# 09 — Decompilation Roadmap (SLUS_206.49)

Quantitative, ranked decompilation plan for the **440 real functions** of
`SLUS_206.49.c`. Generated by `tools/score_functions.py`; it combines call
graph, globals, COP2/VU0, loops, size and known symbols into a single
"decompile soonest" score.

## Data products (src/decomp/analysis/)

| file | content |
|---|---|
| `features.csv` | per-function feature vector + score (440 rows) |
| `call_edges.csv` | caller → callee edges with callee kind (real/stub/unknown) |
| `call_graph.dot` | graphviz call graph (real + stub callers) |
| `leaf_classify.csv` | auto-classified unlabeled leaves |
| `roadmap.md` | ranked categories with scores |

Regenerate:

```powershell
python tools/score_functions.py            # reads src/decomp, writes src/decomp/analysis
```

## Key finding: only 214 of 440 "real" functions have logic

Re-scanning the actual bodies shows the "440 real" census overstates what is
recovered:

| bucket | count | meaning |
|---|---|---|
| **logic** | **214** | body contains real code beyond `halt_*()` |
| pseudo-stub | 226 | body reduces to `halt_baddata()` / `halt_unimplemented()` only — unrecovered |
| symboled (of logic) | 67 | already named via `SYMBOLS` |
| unlabeled logic | 147 | real code, no symbol yet |

So the actionable set is **147 unlabeled functions with real logic** (plus the
67 symboled for graph context). The 226 pseudo-stubs are effectively the same
as stubs and should be tackled only via the raw `.S`/Ghidra, not the C bodies.

## Auto-classification of the unlabeled leaves

`score_functions.py` classifies the 373 unlabeled functions:

| kind | count | action |
|---|---|---|
| `pseudo_stub` | 226 | not recoverable from C; go to Ghidra/asm |
| `vu0_unknown` | 44 | COP2/VU0 macro bodies, no semantic label yet |
| `struct_op` | 43 | field assignment/read mix — most valuable of the leaves |
| `thunk` | 17 | single-call wrapper — name the callee first |
| `setter` | 15 | field writes, returns |
| `convert` | 15 | casts / float math |
| `memcmp` | 8 | compares two structs, returns int |
| `getter` | 4 | reads one field, returns |
| `predicate` | 1 | boolean test on struct fields |

Priority within leaves: **thunks → struct_op → setter/convert → memcmp/getter**.
A thunk's callee is a higher-value target than the thunk itself.

## Priority score

```
score = 3.0 × fan_in                          # how many real functions need this
      + 2.0 × callees_real                    # subsystem reach (real calls)
      + 0.5 × callees_stub                    # frontier into unrecovered code
      + 2.5 × globals                         # singletons / tables / state
      + 3.0 × cop2                            # math / transform kernels
      + 1.5 × loops                           # parsers / iterators / gameplay
      + 1.0 × float_ops                       # float math
      + 0.02 × min(body_bytes, 4000)          # code volume
```

### Type-propagation findings (Phase 3C/D, `tools/propagate_types.py`)

Measured over the **full binary call graph** (45,203 edges incl. stubs) with
sampled Brandes betweenness (`hub_metrics.csv`). The old fan-in list only
covered recovered bodies; the full graph exposes *much* bigger centres.

- **Unidentified mega-utilities (stub, no name, direct fan-in):**
  - `0x00511940` (in=1763, reads ptr@a0+0 + int@0x4c, indirect `jalr`,
    globals `0x720000`) — the single most-called function in the ELF.
    Central API dispatcher.
  - `0x004ba240` (in=1154) and `0x00511860` (in=703, out=0: pure `jalr`
    leaf over `0x720000`), `0x0050fea0` (in=496).
  - `0x00503xxx-0x0051exx` cluster: indirect-thunk wrappers over a global
    table at `0x720000` (consts `lui 0x720000`). **Dispatchers, decompile
    first with Ghidra — naming any of them unblocks hundreds of callers.**
- **Real-symboled fan-in leaders** (new decompile targets): `0x00428f48`
  (in=85), `0x0042bd70` (in=64), `0x0043cb00` (thunk, in=57),
  `0x001207c0`/`0x00120750`/`0x001206f0` (engine copy utils, in=62/54/45),
  `0x0026e060` (in=35), `0x0010e780` (in=22).
- **Type propagation** (`propagated_types.csv`): 87,096 slot labels;
   5,301 struct-typed (`Unknown_*`), 8,291 unique **conflicts** where a
   callee arg disagrees with a caller. Conflicts rank REAL struct
   discoveries: 4,895 are hard (struct-vs-struct / struct-vs-int), e.g.
   `Unknown_a0_4_8` (40 members) colliding with `Unknown_a0_0_1c` (40).
   `type_chains.json` traces each label's propagation edges (446 chained).
